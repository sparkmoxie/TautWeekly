# TautWeekly for Plex v0.9.1

v0.9.1 fixes the movie Rotten Tomatoes fallback used when Tautulli's normal
`get_metadata` response and direct Plex metadata do not provide selected
ratings.

## Diagnosis and correction

Tautulli's current item-export contract accepts one `rating_key`, but
`individual_files` is reserved for library or user exports. v0.9.0 combined
those incompatible options, which Tautulli rejects before creating the export.
It also assumed every download was a ZIP even though a rating-only item export
is a JSON file.

The corrected fallback:

- sends `individual_files=false` for a `rating_key` export;
- requests metadata level 1 and media-information level 0;
- accepts the single JSON download or a ZIP when resources are requested;
- parses Tautulli's flat `ratingImage` / `audienceRatingImage` fields and
  Plex-style nested rating entries; and
- supports ripe, rotten, upright, and spilled Rotten Tomatoes states without
  assigning a provider to an unlabeled number.

The contract is backed by Tautulli's current
[`export_metadata` API implementation](https://github.com/Tautulli/Tautulli/blob/c7153deb6e3017b8dda46c8448fe548a61c5a47a/plexpy/webserve.py#L7134-L7185)
and
[exporter validation](https://github.com/Tautulli/Tautulli/blob/c7153deb6e3017b8dda46c8448fe548a61c5a47a/plexpy/exporter.py#L1861-L1895).

## Independent direct Plex boundary

Issue evidence also showed that the NAS container could not reach its
configured/reported Plex server URL. Posters can still load through Tautulli's
image proxy, so a working poster does not validate direct Plex connectivity.
[Plex's current API](https://developer.plex.tv/pms/) documents
`Accept: application/json`, `X-Plex-Token`, and item keys such as
`/library/metadata/{ratingKey}`; Plex's
[NAS guidance](https://support.plex.tv/articles/200288666-opening-plex-web-app/)
uses the server's reachable LAN address on port 32400.

For Docker, configure `PlexServerUrl` with a trusted address reachable from
inside the TautWeekly container. Do not use that container's localhost for a
Plex server running elsewhere. TV/episode IMDb ratings remain fail-closed
without an IMDb-labelled source, and no logo is invented when the selected
resource is absent.

## Validation and privacy

The sanitized virtual regression makes direct Plex return 404, makes the old
Tautulli option fail with HTTP 400, serves the corrected rating export as raw
JSON, and requires both scores in rendered output. Parser tests cover flat and
nested low-score shapes plus provider-free rejection on Windows, NAS/Docker,
macOS, native Linux, and FreeBSD/Podman renderer sources.

The fallback does not request media information or high metadata levels, so
library file locations and stream details are outside its export. No
configuration, token, recipient, viewing history, generated newsletter, log,
or private infrastructure detail is included in the release.
