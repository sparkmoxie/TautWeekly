# TautWeekly for Plex v0.12.0

v0.12.0 completes the Windows Manager's normal one-off production workflow,
clarifies connection evidence, and makes unlocked local sessions recover
cleanly across Manager updates and restarts.

## Send a production newsletter from the Manager

After reviewing the generated previews and TestEmail delivery, open
**Previews** and use **Send this week's newsletter now**. The control invokes
the same fixed `SendAll` renderer mode used by the Windows schedule and applies
the saved library and delivery exclusions.

The action is intentionally separate from preview and TestEmail controls. It
requires an explicit acknowledgement that real email may be sent to every
currently eligible recipient, cannot be cancelled after starting, and accepts
no browser-supplied command, script, recipient, or user ID. Its dedicated
status card retains only aggregate accepted, skipped, and failed counts.
Recipient identities and raw renderer output are never returned to the
browser or operation history. SMTP acceptance does not prove inbox delivery.

The numbered `11-SEND-ALL-NOW.bat` and PowerShell interface remain packaged for
expert break/fix recovery, but the Manager is now the normal manual-send path.

## Clearer setup and preview evidence

- Generated previews now appear in a fixed scenario order with friendly names:
  Index, Manual Welcome, New User - No History, New User - With History, Normal
  Newsletter, Established Quiet, and Established Warnings.
- A successful Tautulli verification no longer becomes a generic warning when
  the optional direct Plex URL/token pair is omitted. The saved setup result
  states that Tautulli passed and direct Plex was skipped.
- A failed connection check identifies the affected Tautulli or direct Plex
  component in the sanitized setup status and Settings diagnostic list.
- A valid partial production result remains visible with aggregate counts and
  a sanitized support code instead of being collapsed into a generic renderer
  failure.

## Trusted-local update recovery

When the optional Manager password lock is disabled, an already open Manager
tab now renews its local session and CSRF token automatically after the Manager
process restarts during an update. The protected action retries once, so users
do not need to refresh the page or sign in. When the optional password lock is
enabled, the existing password boundary remains authoritative.

## Update from v0.11.1 or an older verified installation

1. Download `TautWeekly-Setup.exe` and `SHA256SUMS.txt` from this release.
2. Verify the EXE against `SHA256SUMS.txt`.
3. Run Setup. It preselects an installer-owned application folder; keep that
   location and confirm **Update**.
4. For an older verified portable/BAT installation, select that exact folder
   and confirm **Migrate**. Setup does not scan drives or guess the location.
5. Open **TautWeekly Manager** from the Start Menu and review Dashboard,
   Config, Previews, and Schedule before the next production send.

Configuration, credentials, library and user choices, delivery history,
generated previews, logs, backups, optional password-lock state, and an owned
Windows Scheduled Task remain private and are preserved by the verified update
or migration process.

## Validation and limitations

The release gates cover Manager unit tests and vetting, JavaScript and
accessibility checks, Windows renderer integration fixtures, cross-platform
Manager builds, Windows install/update/migration/uninstall lifecycle, release
ownership manifests, checksums, privacy boundaries, and reproducible archives.
The production-send tests use fictional aggregate fixtures; automated and live
acceptance do not send real production newsletters.

The Setup executable remains unsigned. Windows SmartScreen may identify it as
an unknown publisher; verify the downloaded file against `SHA256SUMS.txt`.
