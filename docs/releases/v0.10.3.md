# TautWeekly for Plex v0.10.3

v0.10.3 closes a setup and acceptance gap exposed while diagnosing stale or
flattened ratings: successful Tautulli and direct-Plex connectivity checks do
not prove that either upstream metadata store is current.

## What changed

- Every maintained setup wizard, verifier, Quickstart, platform guide, and
  relevant install/update completion path now gives the same ordered sequence:
  1. confirm **Edit > Advanced > Ratings Source** in each included Plex Movie
     library;
  2. run Plex **Manage Library > Refresh All Metadata** for every included
     movie and TV library, then wait for completion;
  3. open each same Tautulli **Library > Media Info** page, select **Refresh
     media info**, then wait;
  4. only then run Verify, PreviewAll, and a controlled TestEmail.
- The guided macOS and QNAP installers pause before automatic verification so
  those manual upstream refreshes can be completed.
- Windows, Unraid/NAS/Docker, native Linux, and FreeBSD paths print the same
  checklist at the point where the administrator transitions to acceptance
  testing.
- The container preview landing page includes the checklist for operators who
  enter through the browser rather than the command-line Quickstart.
- The canonical branding build script now uses byte-preserving Git handling,
  keeping its approved SHA-256 stable across Windows and Unix checkouts.

## Boundaries and safety

Plex documents that **Refresh All Metadata** can take significant time and can
update metadata or artwork. Apply it only to the movie/TV libraries included
in TautWeekly; unrelated music and photo libraries are out of scope.
Tautulli's media-info refresh is per library and updates its table—it does not
replace Plex's metadata refresh or choose the Plex ratings provider.

TautWeekly does not automate either upstream refresh. Routine TautWeekly
updates do not require this full sequence when current ratings and artwork
already render correctly; use it after first setup, a Plex metadata-agent or
Ratings Source change, or a metadata-recovery update when results may be stale.

No configuration, tokens, viewing history, recipient identity, private
infrastructure, upstream responses, logs, or generated newsletter output are
included in the release or its regressions.

## Upgrade

Use the matching v0.10.3 archive or pull
`ghcr.io/sparkmoxie/tautweekly:0.10.3`, recreate the container, and follow the
displayed metadata-readiness note when this update is being used to recover
missing or stale ratings/artwork. Then run the platform verifier and regenerate
PreviewAll. Existing configuration remains compatible. Verify every download
against the release's `SHA256SUMS.txt`.
