# TautWeekly for Plex v0.9.8

v0.9.8 corrects direct Plex rating enrichment when Tautulli returns only the
currently selected, flattened IMDb or TMDB score.

## Diagnosis and correction

The Windows, NAS/Docker, macOS, native Linux, and FreeBSD packages already use
the same rating resolver. The comparative logs showed Windows receiving a
complete Rotten Tomatoes pair from Tautulli before direct Plex was initialized,
while the NAS instance received only selected IMDb/TMDB. That made the shared
direct-Plex fallback decisive on NAS; it was reaching the exact item but did
not explicitly request Plex's optional `Rating` child element.

The direct JSON request now adds `includeOptionalElements=Rating` and
`excludeFields=rating`. The exclusion is necessary because PowerShell's object
model is case-insensitive: Plex's scalar `rating` field can otherwise collide
with and mask the `Rating` array. The exact-episode XML fallback requests the
same optional element without needing that JSON-only exclusion. Movie display
still prefers RT critic/audience and uses labelled IMDb only when no RT value
exists. TV episode rows still accept only IMDb tied to that exact episode.

Direct reachability does not choose a rating provider. For intentional movie
RT output, each applicable Plex Movie library must use **Edit → Advanced →
Ratings Source → Rotten Tomatoes**, followed by a metadata
refresh. This is a library-wide Plex choice. If IMDb or TMDB is intentionally
selected, TautWeekly cannot guarantee an alternate RT pair and keeps labelled
IMDb as the final movie fallback.

Plex documents response customization through `includeOptionalElements`, and
its metadata-provider schema defines `Rating` as an optional array:

- <https://developer.plex.tv/pms/>
- <https://github.com/plexinc/tmdb-example-provider/blob/main/docs/Metadata.md>
- <https://support.plex.tv/articles/advanced-settings-plex-movie-agent/>

## Boundaries and privacy

This changes response-selection parameters on exact item metadata requests. It does not
search by title, contact a new service, change rating priority, synthesize a
score, alter score-dependent RT icons, or broaden the exporter. The Plex token
remains in a request header and no private response, configuration, viewing
history, recipient identity, generated output, or log is included in the
release.

## Validation

A sanitized virtual Plex response returns selected IMDb only unless the
optional `Rating` element is requested; all three maintained renderers must
request it, retain the response in the bounded in-memory cache, recover both RT
values, and request the same optional element for exact-episode XML IMDb. The
existing renderer, full active/quiet newsletter, Preview/SendTest, package,
checksum, reproducibility, and amd64/arm64 container suites remain required.
