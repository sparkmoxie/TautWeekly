# TautWeekly for Plex v0.9.0

v0.9.0 adds a persistent, storage-bounded pre-deletion presentation cache on
every maintained platform. This is a SemVer minor release because upgrades now
create durable private state.

## Future deleted items

While an item still exists, TautWeekly can store its exact stable GUID/media
type, bounded title/year/summary/genres and displayed ratings, plus one
SHA-256-verified poster. PreviewAll, SendTest, and normal scheduled or confirmed
delivery can reuse that record if Plex later deletes the item.

The cache is exact-identifier only. It never falls back to a title or rating
key, so an already-deleted item with a missing or ambiguous stable identifier
remains unresolved.

## Important retroactive limitation

The hosted-provider recovery shipped through v0.8.3 remains best-effort.
Tautulli's [`get_history`](https://github.com/Tautulli/Tautulli/wiki/Tautulli-API-Reference#get_history)
response retains descriptive fields and identifiers, but normal history does
not retain durable poster bytes. Tautulli's
[Exporter Guide](https://docs.tautulli.com/using-tautulli/exporter-guide)
also treats image resources as a separate explicit export. Once Plex/Tautulli
has discarded an asset, TautWeekly cannot reliably reconstruct it.

Accordingly, v0.9.0 protects future items captured live after upgrade. It does
not retroactively fix items already deleted before the cache existed.

## Storage and privacy

- Schema version: 1, with atomic `index.json` replacement and a previous-valid
  `index.backup.json` generation.
- Defaults: 365 days, 1,000 entries, and 256 MiB total. Cleanup is deterministic
  and removes expired/oldest entries, orphans, and damaged poster entries.
- Corruption: recover from the valid backup; otherwise retain at most one small
  corrupt manifest and start empty without blocking newsletter rendering.
- Stored: presentation metadata, one poster/hash, and cache timestamps.
- Never stored: Tautulli API key, Plex/SMTP credentials, Plex administrator
  token, recipients, playback/viewing metrics, or generated newsletters.
- Network: the Plex token is not passed to the cache and is not forwarded to
  third-party artwork hosts.

Existing configurations use bounded defaults without being rewritten. Setup
preserves explicit cache settings. See the
[configuration reference](../CONFIGURATION.md#persistent-deleted-item-cache)
for paths, controls, migration, backup, purge, and uninstall guidance.

## Platform baselines

- Windows Portable 1.8.0
- NAS/Docker Portable 1.2.0
- macOS Portable 1.1.0
- Native Linux 1.1.0
- FreeBSD/Podman 1.1.0

All release ZIP/TAR.GZ packages contain the cache module but no live cache
directory. `SHA256SUMS.txt` covers all nine archives. The GHCR release image is
published for `linux/amd64` and `linux/arm64`.
