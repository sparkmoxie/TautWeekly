# TautWeekly for Plex v0.19.2

v0.19.2 makes active delivery and ready timeline states update truthfully in
the Manager dashboard across every maintained package family.

## Live delivery state

The authenticated dashboard now polls its local Manager status in the
background. Idle dashboards check every five seconds; an active production
delivery checks every 1.5 seconds. Polling pauses while the tab is hidden or
signed out and resumes immediately when the tab becomes visible. It remains a
read-only local status request and does not contact Plex, Tautulli, SMTP, or a
cloud service.

While a scheduled or confirmed all-recipient delivery is active, only the
Delivery card changes to the blue **Running** state. Its badge, card border,
and purple mail icon pulse; the accepted count reads **In progress**. When the
run finishes, the same card transitions automatically to the existing green
**SMTP accepted** state if sanitized renderer evidence records accepted
messages. Inbox delivery is still not asserted.

On Windows, Task Scheduler result `267009` (`SCHED_S_TASK_RUNNING`) is now
recognized as active state instead of being exposed as an opaque task result.
Task identity and ownership must still match the installed TautWeekly task.
Older successful `last-run.json` evidence cannot mask a newer active task.

For NAS/Docker, macOS Docker, native Linux, and FreeBSD, the scheduler writes
its persistent running state immediately before the synchronous renderer
starts. Because the scheduler heartbeat intentionally pauses during that
renderer process, the Manager now combines the running state with the fresh
package-supervisor heartbeat. Long sends therefore remain visibly active for
their full duration without treating an abandoned stale state as live.

## Timeline states

The dashboard now gives three timeline cards state-specific, conservative
emphasis:

- a valid future run glows gold only when the schedule is installed, enabled,
  owned by the package, and ready;
- generated previews glow gold when authenticated indexed preview files are
  available; and
- the latest application attempt glows green only when the recorded production
  result was accepted by SMTP.

The colors remain visible when reduced motion is requested, but the new
animations are disabled.

## Update existing installations

Use the package's normal verified update flow. Windows users can run the new
`TautWeekly-Setup.exe` and accept the detected Update path. Container, macOS,
Linux, and FreeBSD users should use their documented stable updater and
recreate or restart the managed service where instructed. Existing private
configuration, credentials, schedules, history, previews, logs, and welcome
state remain in place.

## Validation

Manager tests cover owned Windows running-state detection, the `267009` task
result, stale successful evidence during a newer run, long embedded-scheduler
runs with a stale scheduler heartbeat and fresh supervisor heartbeat, and all
frontend state contracts. The Manager is cross-built for Windows, Linux,
macOS, and FreeBSD on amd64 and arm64. Desktop and 390-pixel mobile browser QA
verified the running-to-SMTP-accepted automatic transition, responsive card
layout, generated-preview gold state, and no horizontal overflow. Full Go,
accessibility, branding, platform, documentation, PowerShell, scheduler, package,
reproducibility, and Windows installer checks remain enforced by the release
workflow.
