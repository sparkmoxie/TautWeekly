What the Windows host needs

Plex and Tautulli may run on the same computer, another LAN server, a NAS, or a container host.

  • 64-bit Windows 10 or 11
  • Windows PowerShell 5.1 or newer
  • Tautulli URL and API key
  • SMTP host with STARTTLS support
  • Recommended direct Plex URL and token

Use an address reachable from this PC

Use 127.0.0.1 only when the target service is on this computer. For another LAN host, use its resolvable hostname or private address. Setup needs no separate Go, Node.js, Docker, or web-server installation.

Normal setup is unelevated.

Administrator approval is requested only when the Manager changes the optional Windows Scheduled Task.

Fresh installation

Download, verify, and run Setup

The installer owns application files while leaving configuration and generated data private and update-safe.

1

Download both release files

Get TautWeekly-Setup.exe and SHA256SUMS.txt from the same latest release.

2

Verify the SHA-256 value

PowerShell
Get-FileHash .\TautWeekly-Setup.exe -Algorithm SHA256

Match the result to the Setup line in SHA256SUMS.txt.

3

Choose a permanent folder

Run Setup, select an empty permanent writable folder, and confirm the action reads Install. The default is %LOCALAPPDATA%\Programs\TautWeekly.

4

Open the Manager

Setup always adds the Start Menu launcher and adds a Desktop launcher when Windows exposes a usable Desktop. It registers uninstall information, starts the local Manager, and opens it at 127.0.0.1:8788.

Unsigned release notice.

Windows SmartScreen may report an unknown publisher. Confirm the official SHA-256 value before choosing Run anyway.

First launch

Start on the Dashboard

Windows trusted-local access opens directly. No pairing token or password is required for initial configuration.

01

First time setup

A fresh installation shows a glowing blue First time setup card. Select Setup to open Config.

02

Existing configuration

A migrated config.json is loaded with stored secrets preserved. Review it and validate without retyping unchanged credentials.

03

Optional lock later

The header lock icon links to Settings. Add a password only when other people can use the same Windows account.

Safe local save and deliberate recovery.

A private timestamped backup is created before config.json is replaced. The newest 10 are retained automatically. Configuration backups can be restored, or one can be permanently deleted only after Confirm delete; deletion leaves the live configuration unchanged.

One safe action

Validate, save, and verify

The Manager runs every applicable non-intrusive setup check, records the results, and does not send email.

01

Libraries and users

Loads active movie/TV libraries plus sanitized user IDs, friendly names, and roles for guided selection.

02

Tautulli and Plex

Verifies the saved Tautulli API and configured direct Plex identity and authenticated library access.

03

SMTP preflight

Checks DNS/TCP, greeting, EHLO, and certificate-validated STARTTLS without authenticating or submitting a message.

04

Local previews

Starts all six local states when one unambiguous owner/admin ID and required metadata are available.

The four status cards are persistent.

They survive browser refresh and Manager restart for the current saved configuration and appear together in Dashboard Config status. A later validation replaces them.

Validation remains non-sending.

It never authenticates to SMTP, sends email, changes welcome state, or installs a schedule.

Acceptance

Preview first, TestEmail second

Every preview uses the production renderer: manual welcome, two new-user states, and normal, quiet, and warm-up established-user states.

6

Inspect local HTML

Review artwork, ratings, summaries, conditional sections, personal statistics, and responsive behavior. No mail is sent.

@

Send a controlled test

Select the owner/admin user and confirm Send six test messages. Every message goes only to the configured TestEmail.

SMTP acceptance is not inbox delivery.

Verify all six messages in a real mail client before scheduling production delivery.

Windows delivery lifecycle

Install automation last

The Manager reports observed Task Scheduler state and exposes only four typed lifecycle actions.

1

Select Install

Approve the narrow Windows UAC prompt only after Config, previews, and TestEmail are accepted.

2

Verify the observed task

Confirm ownership is Verified, state is Ready, and the upcoming local run is correct.

3

Refresh after task-relevant changes

Once installed, the primary button smoothly changes from Install to Refresh. Enable, Disable, and Remove remain separate actions.

The browser never supplies a command.

The helper validates the saved revision and exact task ownership before changing Windows Task Scheduler.

Settings status + verified updater

Check, Install, Update, or Migrate

Start in Settings > Updates. It reports the running application and installed package separately, renders cached status immediately, and performs one bounded background refresh only when the last successful check is missing or at least 24 hours old and backoff permits. The main header Refresh reloads local status first and then starts that check only when the new typed status recommends it; it never waits for GitHub, while scoped refresh controls stay isolated. Successful results are reused for five minutes; Check now then explicitly refreshes the same endpoint. Current retains its green glow, every non-current status gives the update card an attention glow, and the purple header SVG appears only after a successful check validates a newer running application. Normal health remains offline-capable.

Windows is the only Manager with an Install update button.

After a fresh verified check and separate confirmation, the Manager starts the existing fixed updater. It accepts no browser-supplied URL, path, version, command, or arguments; Windows elevation, checksums, the internal manifest, backup, health verification, and rollback still apply. No unattended updater is installed.

Optional private remote access

Private HTTPS through your tailnet

Settings can create and verify one exact Tailscale Serve route without making the Manager public.

TS

Install, sign in, enable

Install Tailscale on this Windows host and every remote computer or mobile device. In Settings > Tailscale, enable private access and approve the fixed Windows helper.

HTTPS

HTTPS only; Funnel off

If Tailscale opens its consent page, enable HTTPS certificates only and turn Funnel off. TautWeekly never needs a router port or public URL.

The Windows password lock stays optional.

Tailnet policy decides who can reach the host. With the Manager lock off, every permitted tailnet user or device receives full Manager administration; there is no read-only role. Local loopback access remains the recovery path.

Optional Manager lock

Local access, your way

Windows trusts the current account by default. Add the browser lock only when that extra boundary is useful.

U

Unlocked by default

No first-run pairing token is required. A gold unlocked icon reports Browser access unlocked and links to Settings.

L

Optional password lock

Use at least 8 characters. Enable or change the lock under Settings. A green icon reports Browser access locked. Passwords are stored only as a salted local verifier.

Recovery does not erase TautWeekly.

Use the Start Menu Reset TautWeekly Manager Access shortcut or Reset-TautWeekly-Access.cmd. Only the Manager lock is disabled; configuration, credentials, schedules, history, and previews remain.

Private local record

Know what is preserved

Do not commit, publish, or attach live configuration, tokens, recipient identity, viewing history, generated newsletters, logs, or backups.

C

Application data

config.json, state, cache, output, previews, logs, and custom assets remain private and update-safe.

M

Manager data

Access policy and sanitized history live under %LOCALAPPDATA%\TautWeekly\data.

D

Diagnostics

Review sanitized support codes under Settings > Build and diagnostics. Setup logs to %LOCALAPPDATA%\TautWeekly\installer.log.

When output is incomplete

Refresh Plex, then Tautulli

Use this after first setup, after changing a metadata agent or Ratings Source, or when ratings and artwork remain stale.

1

Confirm Ratings Source

In every included Plex Movie library, review Edit > Advanced > Ratings Source.

2

Refresh Plex

Run Manage Library > Refresh All Metadata for every included movie and TV library and wait.

3

Refresh Tautulli per-library

Open each same Library > Media Info page, select Refresh media info, and wait.

4

Validate again

Return to Config, select Validate, save, and verify, and inspect the replaced local previews.

Scope the work.

Do not refresh unrelated music or photo libraries. Routine TautWeekly updates do not require a full refresh when current output is already correct.

Quick diagnosis

When a step needs review

Use the persistent Config cards, Verify evidence, Schedule observation, and sanitized support codes to isolate the boundary.

Setup does not show Migrate

Cancel. Select the exact extracted release folder with its ownership manifest, not the parent folder or another non-empty directory.

A service works on another PC only

Confirm its firewall, listening address, and URL are reachable from the Windows computer running TautWeekly.

Previews were skipped

Complete metadata readiness, confirm one unambiguous owner/admin ID, then validate again.

Schedule action was interrupted

Refresh Schedule and review observed Windows state before retrying the explicit action.
