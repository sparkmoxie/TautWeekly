GUI-first install

Install once, configure in Manager

Use a permanent extracted directory. The installer detects your Mac identity, builds the correct architecture, preserves existing private data, and keeps access on loopback by default.

1. Verify and extract

Download the Mac archive and SHA256SUMS.txt from the same stable release, verify SHA-256, and extract to its permanent location.

2. Start Docker Desktop

Wait until docker info succeeds. Both Intel and Apple silicon are supported by packaged amd64/arm64 Manager binaries.

3. Run the installer

chmod +x INSTALL-MAC.command mac-install.sh tautweekly.sh mac-update.sh check-release.sh package-update.sh app/*.sh app/bin/*.sh
./mac-install.sh

No default password

Run ./tautweekly.sh manager-bootstrap, open http://localhost:8787/, enter the one-time token, and create the administrator password. The token is absent from Docker logs and invalid after pairing.

Main features

Shape the newsletter in Manager Config

Normal configuration no longer uses the terminal wizard. These are the everyday controls; the full reference covers advanced renderer fields.

Connections and delivery

Add Tautulli, recommended direct Plex, SMTP, sender identity, and a controlled TestEmail. Saved secrets remain write-only.

Library selection

Choose the movie and TV libraries that define release, Trending, and personal-stat content. Unselected sections do not contribute.

User exclusions

Review the discovered roster and exclude anyone who should not receive production mail. Excluded users remain available for safe preview and TestEmail sampling.

Newsletter and custom text

Set lookback, card limits, branding, and the optional custom text card. Its body is required when enabled; title, six-choice local title GIF, subheading, and border are optional.

Verify and PreviewAll

Select Validate, save, and verify, confirm library/user discovery and non-sending connectivity checks, then inspect all six previews.

TestEmail and Schedule

Send the six controlled messages only to TestEmail. Enable future starts after content, recipients, timezone, and inbox rendering are correct.

Prepare Plex and Tautulli metadata

Connection checks cannot prove upstream metadata freshness. Use this sequence after first setup, agent or Ratings Source changes, or a ratings/artwork recovery update.

  1. Confirm Plex Movie Edit > Advanced > Ratings Source for each included library.
  2. Run Plex Manage Library > Refresh All Metadata for every included movie/TV library and wait.
  3. In Tautulli, open each same Library > Media Info tab, choose Refresh media info, and wait. The current control is per-library.
  4. Return to Manager Verify, PreviewAll, and TestEmail.

Routine TautWeekly updates do not require a full refresh when current output already renders correctly.

Local by default, explicit when remote

Mac-hosted services

Use host.docker.internal for Plex or Tautulli running directly on the Mac. Container localhost refers to TautWeekly itself.

Manager access

The compatibility variables PREVIEW_BIND and PREVIEW_PORT publish the authenticated Manager; the installer sets 127.0.0.1:8787.

TLS proxy

Allowlist exact DNS names with MANAGER_ALLOWED_HOSTS, preserve Host, set MANAGER_SECURE_COOKIES=true, and never publish plain HTTP. Cloudflare Tunnel routes must omit httpHostHeader overrides so the public Host reaches the Manager unchanged. /health/live exposes liveness only.

Private Tailscale Serve

tailscale serve --bg --yes --https=443 http://127.0.0.1:8787

Install/sign in to the native Mac client, enable HTTPS certificates only with Funnel off, then paste the exact .ts.net URL into Settings > Tailscale. For optional mobile use, sign the phone or tablet into the same tailnet with the Tailscale app before opening that URL. The Manager password remains required and every remote session has full administration. The archive also includes a Docker-only userspace sidecar fallback with no Docker socket, TUN device, or added capability.

Settings status, host-owned update

Update without replacing private data

Settings > Updates separately reports the running application/image, extracted Mac package, host-adapter compatibility, stable release, check history, sanitized failure, and release notes. Authenticated entry renders cached status first, then performs one bounded background refresh only when the last success is missing or at least 24 hours old and backoff permits. The main header Refresh reloads local status first and then starts that check only when the new typed status recommends it; it never waits for GitHub, while scoped refresh controls stay isolated. Successful results are reused for five minutes; Check now then explicitly refreshes the same endpoint. Current remains green, every non-current status gives the update card an attention glow, and the purple header SVG appears only after a successful check validates a newer running application. Normal health stays offline-capable. The browser cannot invoke Docker Desktop and instead provides the copyable ./tautweekly.sh update host command.

1. Back up

./tautweekly.sh backup

Keep the archive private.

2. Check and apply

./tautweekly.sh check-update
./tautweekly.sh update

The wrapper downloads the stable archive and SHA256SUMS.txt, verifies the published checksum and internal manifest, then refreshes release-owned files without replacing .env or data/.

3. Accept in Manager

./tautweekly.sh open-manager

Sign in, confirm version and health, then repeat Config status, all six previews, and controlled TestEmail.

Automatic rollback

The updater refuses an active renderer operation, builds the verified package, checks image version and liveness, and restores prior package files and image if the candidate fails. The graceful stop allows up to 30 minutes for an already-running newsletter to finish.

One-time bridge from v0.14.0 or an image-only wrapper

If Settings reports a legacy host adapter, verify and extract the current stable Mac Docker archive over the same package directory without deleting .env or data/, then run update. That installs the shared package updater; later runs advance and roll back host files and image together.

Recovery and data ownership

Password recovery

./tautweekly.sh manager-reset-access
./tautweekly.sh manager-bootstrap

Only Manager credentials and sessions reset; configuration, schedules, history, output, and delivery state remain.

Reinstall

Extract the same verified archive over the package, preserve .env and data/, and run update. The image is read-only; writable state stays in the private bind mount.

Uninstall

Stop the service and retain a private copy of .env and data/. Delete them only when you explicitly want configuration, credentials, schedules, output, and cache erased.

Truthful limitation

This is a Docker Desktop Manager, not a native notarized .app, menu-bar item, Login Item, or macOS background agent. A physical Intel/Apple-silicon Mac and Docker Desktop remain final hardware acceptance gaps when CI cannot provide them.

In Manager Config > Configuration backups, Delete requires a second confirmation and permanently removes only that backup; it does not alter the current configuration.

Basic troubleshooting

Check the boundary that failed

Start with Manager status and Docker Desktop; keep private credentials, generated output, and raw logs out of public support reports.

Manager does not open

Confirm Docker Desktop is running, docker info succeeds, and the TautWeekly container is healthy. Reopen with ./tautweekly.sh open-manager.

Verify cannot reach a service

For Plex or Tautulli on the Mac, use host.docker.internal; container localhost points back to TautWeekly. Confirm LAN firewalls and the saved URL.

Preview is skipped or incomplete

Confirm one owner/admin sample, selected libraries, and metadata readiness. Save and verify again before regenerating all six previews.

TestEmail or schedule fails

Keep production disabled. Recheck SMTP, sender permission, TestEmail, exclusions, timezone, and the saved revision, then inspect the sanitized operation result.
