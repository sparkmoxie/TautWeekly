v0.9.0 storage boundary

Future deletion protection, not retroactive reconstruction

The v0.8.3 Plex hosted-provider recovery is best-effort. Tautulli history can retain identifiers and descriptive fields, but not durable artwork bytes after Plex/Tautulli discards them.

v0.9.0 stores the minimum newsletter presentation metadata and one poster under private platform storage, then reuses it after a future deletion. It never title-matches ambiguous old history and cannot repair assets deleted before the cache was populated.

Upstream readiness

Refresh metadata before acceptance

Use the same upstream sequence on every platform.

01

Confirm the movie source

In every included Plex Movie library, confirm Edit → Advanced → Ratings Source.

02

Refresh Plex

Run Manage Library → Refresh All Metadata for every included movie/TV library and wait.

03

Refresh Tautulli

Open each same Library → Media Info tab and select Refresh media info. Repeat per library and wait.

Plex warns that full-library refreshes can take significant time and can update metadata or artwork. Do this after first setup, after a Plex agent/source change, or after a ratings/artwork recovery update when data may be stale. Routine TautWeekly updates do not require it when current output is correct. Tautulli's step updates its table; it does not replace the Plex refresh.

Credential boundary

Runtime data is never source data.

Live configuration contains an SMTP credential and Tautulli API key, and may contain a Plex token. State, logs, previews, and backups may reveal recipients and server activity. Weekly Binge Champion cards share only anonymous watch time plus nonzero unique movie/TV-show counts; the champion's identity and titles remain private.

Read the hardening guide
  • Never commit live config or `.env`
  • Keep port 8787 private
  • Binge Champion identity stays private
  • Use application passwords
  • Rotate exposed credentials
